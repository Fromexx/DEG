# ДЭГ СПК — минимальный фронтенд

Подготовлено отдельно от репозитория. Существующие файлы проекта не менялись.

## Что внутри

- React + TypeScript + Vite (без дополнительного UI-фреймворка).
- Адаптивная панель навигации.
- Главная, мероприятия, голосования, участники и управление.
- Переключение ролей для демонстрации интерфейса.
- Регистрация на мероприятие, голосование и создание мероприятия работают локально в состоянии React.
- Попытка авторизации в Telegram Mini App через существующий `GET /api/me`.
- Vite proxy для `/api` направлен на `http://localhost:3000`, потому что backend `src/index.ts` сейчас использует порт 3000 по умолчанию.

## Установка

Скопируйте содержимое архива в существующую папку `frontend/`, сохранив имеющиеся `package.json`, `package-lock.json`, `tsconfig*.json` и настройки линтера.

Замените/добавьте:
- `src/main.tsx`
- `src/App.tsx`
- `src/App.css`
- `src/index.css`
- `src/api.ts`
- `src/types.ts`
- `index.html`
- `vite.config.ts`

Затем:

```bash
cd frontend
npm install
npm run dev
```

Проверка production-сборки:

```bash
npm run build
```

## Текущие ограничения интеграции

На просмотренной ветке `feature/backend` Express пока предоставляет только:
- `GET /`
- `GET /api/me` (защищён `authMiddleware`, заголовок `Authorization: tma <Telegram initData>`)

В Prisma schema уже описаны User, Event, EventRegistration, Poll, PollOption, Vote и AuditLog, но CRUD/API-маршрутов для них пока нет. Поэтому экранные данные и изменения мероприятий/голосований/участников сейчас демонстрационные и не сохраняются на сервере.

Когда backend-разработчик добавит маршруты, нужно будет согласовать контракт и заменить локальные обработчики в `App.tsx` вызовами API. Важные моменты:
- backend должен сам проверять роль и права доступа;
- фронтенд может скрывать недоступные разделы, но это не защита;
- текущий `/api/me` отдаёт Telegram user из initData, а не запись Prisma User с ролью. Для реального ролевого интерфейса endpoint должен возвращать профиль приложения, включая `role`, `isBanned`/статус и необходимые поля.

## Как устроен фронтенд

- `main.tsx` — точка входа: находит `#root` и монтирует React-приложение.
- `App.tsx` — основной экран, состояние, навигация, формы и компоненты карточек.
- `types.ts` — TypeScript-типы ролей, страниц, мероприятий и голосований.
- `api.ts` — изолированное место для HTTP-запросов и Telegram initData.
- `index.css` — глобальные стили и CSS-переменные.
- `App.css` — стили компонентов и адаптивная раскладка.
- `vite.config.ts` — конфигурация dev-сервера и прокси на Express.

## Конфигурационные файлы проекта

- `package.json` — зависимости и команды `dev`, `build`, `lint`, `preview`. Для этого интерфейса новых npm-пакетов не требуется.
- `package-lock.json` — точная фиксация версий npm-зависимостей; вручную редактировать не нужно.
- `vite.config.ts` — подключает React-плагин и перенаправляет `/api` на backend.
- `tsconfig.json` — объединяет конфигурации TypeScript для приложения и конфигурации Vite.
- `tsconfig.app.json` — настройки проверки `.ts/.tsx` приложения, включая строгую проверку типов и JSX.
- `tsconfig.node.json` — настройки TypeScript для `vite.config.ts`.
- `eslint.config.js` — правила статического анализа кода.
- `biome.json` — отдельная конфигурация Biome, уже имеющаяся в проекте; этот фронтенд на неё не завязан.
- `index.html` — HTML-шаблон, в который Vite подключает `src/main.tsx`.

## Что нужно согласовать с backend

1. Формат `GET /api/me`: `id`, ФИО, Telegram username, cardNumber, role, isBanned/isActivated.
2. Маршруты мероприятий: список, создание, изменение, регистрация/отмена регистрации.
3. Маршруты голосований: список, создание, отправка голоса; отдельное право на просмотр статистики.
4. Маршруты участников: создание активиста, импорт базы, изменение роли (только admin), бан/разбан.
5. Формат загрузки файла базы участников (CSV/XLSX) и ограничения по размеру.
6. Подтвердить порт backend. В коде backend по умолчанию 3000; proxy настроен на 3000.
