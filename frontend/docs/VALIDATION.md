# Проверки и границы результата

Дата: 17.11.2026. Node 24.22.1. React/TypeScript/Vite и тестовые инструменты установлены по package-lock.json.

## Выполнено

- `npm run build`: TypeScript strict и production-сборка Vite.
- `npm run lint`: ESLint.
- `npm test`: 18 проверок (5 unit + 13 DOM/React).
- Форматирование исходников для читаемости.

Unit-проверки: матрица прав; запрет неизвестного, неактивного и заблокированного профиля; смешанная лента, скрытые записи, пересечение id событий/опросов; поиск и актуальность; пропорциональное перераспределение, округление, равные остатки, нулевые/некорректные данные. Дополнительно перебираются 2800 комбинаций распределения и доли с проверкой сохранения суммы и отсутствия отрицательных/дробных результатов.

DOM/React-проверки: отсутствие API-запросов без Telegram; отказ в доступе при старом /me без DB-role; пустой интерфейс; подпись в заголовке; запись/отмена; подтверждённый голос; отсутствие статистики у участника/модератора; отсутствие ложного успеха при 500; отсутствие вызовов отключённых API; multipart-создание; блокировка диалога при запросе; серверный preview/commit перераспределения; снятие доступа после 403; частичная ошибка ленты; повтор загрузки галереи без дублирования мероприятия; двухэтапный CSV; подтверждение смены роли; сохранение старой обложки и UTC-момента при редактировании.

Все тестовые данные изолированы в tests. Сами тесты не обращаются к реальному GitHub, боту, БД или API сервера пользователя.

## Что не подтверждено в этой среде

- 12 Playwright-сценариев подготовлены, но реальный браузерный прогон остановился **до выполнения сценариев**: Chromium не смог создать системный сокет (`Operation not permitted`). Поэтому эти сценарии нельзя считать прошедшими; DOM-тесты не доказывают корректность геометрии и мобильной вёрстки.
- Визуальная проверка в настоящем Telegram WebView и мобильном браузере не выполнена.
- Сквозные проверки с действующим Express/SQLite/Telegram не выполнялись. Отсутствующие API описаны в API.md, не выдаются за работающие.
- Не проверялись реальные загрузки фотографий в серверное хранилище, серверный импорт CSV, миграции multiple-голосования, атомарность и аудит корректировок. Это ответственность backend и этапа интеграции.

## Локальный браузерный прогон

```bash
cd frontend
npm ci
npx playwright install chromium
npm run test:e2e
```

Playwright сам запускает Vite. Для уже установленного Chromium при необходимости задайте `CHROMIUM_PATH`. В tests/browser есть проверки ширины 390/320 px, доступа, форм, серверных ошибок, статистики, импорта и галереи. Снимок экрана сохраняется в test-results, не в исходники приложения.

## Реальная приёмка после реализации API

Проверить три настоящие роли через бота, запрет прямых запросов без прав, запрет чтения результатов участником/модератором, сохранение изображений после редактирования, повторную запись/голосование, закрытые и просроченные опросы, импорт с ошибками/дубликатами, конкурентное голосование во время preview, устаревший preview (409), повтор commit, сохранность исходных бюллетеней и аудита, блокировку последнего администратора, полноту выдачи больших списков. Текущий контракт возвращает массивы целиком; серверная пагинация в объём этого frontend не входит.
