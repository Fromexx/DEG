# ДЭГ СПК — локальный frontend для feature/frontend

Подготовлено 17 ноября 2026 по «дэг спк(1).docx», уточнениям пользователя, приложенному frontend и прочитанным веткам feature/backend и feature/bot. GitHub использован только для чтения. Backend, бот и удалённые ветки не изменялись.

## Что находится в архиве

Полный каталог `frontend/`: React + TypeScript + Vite, конфигурация, lock-файл, исходники, тесты и контракты API. В отличие от исходного архива, пакет не требует отдельно восстанавливать package.json, index.html и tsconfig.

Нет предзаполненных мероприятий, пользователей, голосов, seed-скриптов, переключателя тестовой роли или сохранения вымышленных данных в localStorage. Фикстуры находятся только в tests и не попадают в production-сборку.

## Перенос в ваш репозиторий

1. Сохраните свои незакоммиченные изменения и сделайте резервную копию текущего frontend.
2. В локальном клоне DEG создайте ветку от согласованной базы. Например, если базой выбран актуальный backend:

```bash
git switch feature/backend
git switch -c feature/frontend
```

Если `feature/frontend` уже существует, выполните `git switch feature/frontend`, не пересоздавайте её. Команды выше предполагают, что feature/backend уже есть локально; пакет сам не выполняет fetch, commit или push.

3. Перенесите каталог `frontend` из архива в корень DEG. Он заменяет предыдущую локальную заготовку frontend. Каталоги backend и bot не трогайте. Если в frontend есть собственные доработки, сначала сравните файлы.
4. Используйте Node.js 22.18+ (проверено на Node 24.22.1):

```bash
cd frontend
npm ci
npm run dev
```

Адрес: http://localhost:5173. Express по умолчанию ожидается на http://localhost:3000. При необходимости скопируйте `.env.example` в `.env` и поменяйте `BACKEND_URL`. Прокси загружает .env через Vite loadEnv. Не помещайте BOT_TOKEN в frontend.

## Важное ограничение подключения

**Текущий backend ещё не позволяет полноценно запустить все сценарии ТЗ.** `/api/me` возвращает только Telegram-пользователя без роли и статуса профиля из БД. Поэтому приложение не выдаёт права на основании предположений: с текущим ответом оно покажет «Профиль ещё не готов». Без Telegram initData — предложение открыть приложение через бота. Это не ошибка сборки.

Первый необходимый шаг backend-разработчика: проверить Telegram initData, найти активного пользователя в БД и вернуть согласованный `/api/me`. Затем включать capabilities только для реально готовых маршрутов. Полный контракт и обнаруженные ошибки — [docs/API.md](docs/API.md).

Для Telegram Mini App нужен доступный HTTPS-адрес frontend, указанный в WEB_APP.URL бота. localhost с телефона недоступен. В production раздавайте `dist/` и проксируйте `/api`, `/uploads` к Express на том же origin. Vite dev proxy не входит в production-сборку. Flask не добавлялся: действующая интеграция остаётся Express + aiogram3.

## Интерфейс

- Две верхние вкладки: «Лента», «Управление». Управление доступно только подтверждённым модераторам и администраторам.
- Мероприятия, собрания и голосования в общей ленте. Тип, важность и актуальность переключаются фильтрами. Есть поиск и группировка по дате создания. Важные актуальные записи вынесены наверх без дублирования.
- Подробности открываются в диалоге. Даты отображаются в часовом поясе устройства; сервер получает ISO UTC.
- Мероприятия: создание, редактирование, удаление, описание, место, время, важность, обложка, дополнительные фотографии, скрытие, регистрация/отмена регистрации, список записавшихся. Обложка — существующий multipart API; галерея, тип и скрытие требуют расширения backend.
- Голосования: создание с одним/несколькими вариантами, срок завершения, голосование, завершение. Участник и модератор видят «Голос учтён», без статистики. Только администратор получает статистику и перераспределение.
- Перераспределение: выбрать вариант, указать процент и причину, получить серверный расчёт и подтвердить. Чистая эталонная функция пропорционального налога приложена для backend; клиент не меняет счётчики самостоятельно.
- Участники: создание по ФИО, Telegram ID, username, номеру карточки; CSV с предварительной проверкой; поиск; блокировка/разблокировка. Только админ меняет роли. Роль новых участников всегда participant.
- Обслуживание: предварительный расчёт объёма очистки и подтверждение словом УДАЛИТЬ. Участники и аудит должны сохраняться.
- Ошибки загрузки отличаются от пустых состояний. Нет «успешно» до ответа сервера. Повторные отправки блокируются. При 401/403 привилегированный интерфейс закрывается.

Из двух документов выбрана компактная архитектура из вашего сообщения: две верхние вкладки, а мероприятия/голосования — фильтры общей ленты. Специфика ролей взята из актуального «дэг спк»: модератор имеет общие операции управления; назначение ролей, статистика и перераспределение — только админ. Очистка доступна обеим управляющим ролям по capability, поскольку документ уравнивает их остальные права.

В исходном zip стоковых обложек нет; вымышленные ссылки на них не добавлялись. Есть загрузка своих фотографий и предпросмотр.

## Структура

| Каталог | Назначение |
|---|---|
| src/components/layout | Верхняя навигация и профиль |
| src/components/feed | Фильтры и карточки общей ленты |
| src/components/events | Формы, подробности, управление мероприятиями |
| src/components/polls | Создание, голосование, результаты, перераспределение |
| src/components/users | Участники, роли, импорт |
| src/components/management | Обслуживание данных |
| src/components/common | Диалоги и состояния |
| src/context | Сессия и блокировка диалога при отправке |
| src/hooks | Загрузка ленты и контроль асинхронных действий |
| src/pages | Композиция двух страниц |
| src/services | Все точки взаимодействия с Express |
| src/types, src/utils | Типы, права, даты, фильтры, алгоритм |
| src/styles | Адаптивная вёрстка |
| tests | Изолированные unit, DOM и браузерные сценарии |

Точки зависимости помечены `BACKEND`, `BACKEND REQUIRED`, `BACKEND COMPAT`. Найти: `rg 'BACKEND' src`.
